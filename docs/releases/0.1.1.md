# @arthav/open-loading 0.1.1 Release Notes

Draft notes for the first public package cut.

## Highlights

- Ships 15 accessible React loading components across AI thinking, inline, page, skeleton, uploading, empty, error, waiting-room, and experimental categories.
- Adds direct gallery permalinks so docs, issues, and release notes can link to individual loaders.
- Adds explicit stylesheet support through `@arthav/open-loading/styles.css`, while keeping a singleton runtime style fallback for quick prototypes.
- Adds registry-driven docs and tests so component exports, metadata, accessibility behavior, reduced motion, and error support stay aligned.
- Adds Vite React and Next.js App Router examples that consume the package like real apps.
- Adds a tarball consumer smoke check that packs the library, installs it into a temporary app, typechecks public imports, builds with Vite, and server-renders all registered loaders.

## New Loaders

- `RouteReveal` for page and route transitions.
- `ButtonHold` for compact button submits and toolbar actions.
- `DataTableSkeleton` for admin tables and query results.
- `EmptySearch` for searches, filters, and first-run checks that may resolve empty.
- `ToolCallTrace` for AI agents actively calling tools.
- `FileImportStack` for parsing, validating, and saving uploaded rows.

## Package Notes

- Package name: `@arthav/open-loading`
- Public stylesheet path: `@arthav/open-loading/styles.css`
- Peer dependencies: React and React DOM `18.2.0` or newer, including React 19.
- Root workspace remains private; only `packages/core` is published.

## Verification

Run before publishing:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm pack:core
pnpm smoke:core-tarball
```

Expected package dry-run contents include `dist/styles.css`, `dist/loaders/FileImportStack.js`, loader type declarations, registry files, and `README.md`.

## Known Boundaries

- `ProgressPulse` is intentionally non-determinate. It does not expose fake exact progress.
- Loader styling is namespaced with `ol-` classes and CSS variables, but consumers with very aggressive global resets should still verify visuals in their product shell.
- Visual QA is still manual through `docs/visual-qa-checklist.md`; screenshot automation can come later.
